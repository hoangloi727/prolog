# 7 Part D: The Report and the Defence

## 7.1 D1: Report

Submit a 15-20 A4-page report, excluding cover page, table of contents, references, code appendix, and full test appendix. Required structure:

1. Abstract (120 words): what was built, coverage, and failures.
2. Introduction and scope: covered chapters and constructions, plus deliberate exclusions.
3. Feature system: formal attribute-value presentation of feature records and what unification does and does not enforce; readable without Prolog knowledge.
4. Implementation: one subsection for each B1-B4 extension, showing a key rule rather than the full file and explaining a rejected alternative.
5. Evaluation: metrics table, minimal pairs, and ambiguity analysis.
6. Error analysis: as required by Part C3.
7. Limitations and future work: specific limitations, not a generic claim that the grammar is incomplete.
8. Contribution statement: primary author and cross-reviewer for B1-B4, testing, integration, and every report section.

For each B component, include the linguistic phenomenon, at least one phrase marker, relevant feature structure, key DCG rule, variable-sharing explanation, one minimal pair, one error analysis, and one rejected alternative. Report code is illustrative only; do not include more than 15 lines of Prolog in a single figure.

## 7.2 D2: Individual Defence

Each team member is examined separately for 10-12 minutes. Be able to explain one primarily owned rule and one partner-owned rule, predict an unseen test result, diagnose one failure, and make a small live modification. Both members are responsible for the complete grammar.

## 7.3 D3: Individual Contribution Evidence

Submit a dated joint journal, contribution matrix, and version-history evidence. Each component must identify a primary implementer and cross-reviewer; unsupported claims receive no credit.
